# CLAUDE.md — Project Instructions for useyona/einvoice-php

This file provides context for Claude Code and any AI agent working on this project.

## Project Overview

PHP SDK for the Yona e-invoicing API, the port of `@useyona/einvoice-js`
(`Elyonar/einvoice-js`, locally `../elyonar-sdk`) module for module. It covers **exactly what an
API key may call**: invoicing, submissions to the tax authority, output and share
links, items, reference data, buyers, the read-only seller, received invoices and issued history,
invoice settings, the tax connection, the organisation (read), billing reads and webhooks (read,
test, redeliver). Users, invitations, roles, API keys, organisation management, collections,
purchases and webhook-endpoint writes are user-only and are not in the SDK.

PHP 8.1+. Composer package `useyona/einvoice-php`, namespace `Useyona\EInvoice\` (PSR-4 → `src/`).
Runtime dependencies: `psr/http-client`, `psr/http-factory`, `psr/http-message`, `php-http/discovery`;
no HTTP client is required: one is discovered (Guzzle when installed) or injected. The SDK's own
version is `Version::VERSION` (0.1.0); the SDKs are versioned independently of einvoice-js.

## Source of truth

- **einvoice-js is the source of truth for every Yona SDK.** `make sync` fetches it at the commit
  (or tag) pinned in `scripts/sync.sh` (`EINVOICE_JS_REF`) and copies three things:
  `scripts/openapi-api-key-ops.json` (the API-key operations of the gateway's OpenAPI),
  `tests/vectors/webhook-signature.json` (the backend-signed webhook test vectors) and the generated
  models `src/Generated/Types.php` (rendered by einvoice-js's `scripts/gen-types.mjs --lang php`).
  Never edit those three by hand. `make sync-check` (CI) fails when any differs from the pinned
  commit. Bumping the pin is how this SDK takes a new API surface.
  `EINVOICE_JS_DIR=../elyonar-sdk make sync` uses a local checkout (development).
- **Parity is enforced** by `tests/ParityTest.php`: every SDK method must call exactly one snapshot
  operation; every snapshot operation must have a method or an entry (with a reason) in
  `ExcludedOperations`; `Idempotency-Key`s are generated exactly on the POST/GET routes that
  accept one; 99 methods in 23 modules.
- The transport contract, the exception hierarchy, the webhook verification and the method names
  (the same `camelCase`) mirror einvoice-js `src/`; when in doubt, read the TypeScript and its tests.

## Key rules

- **Host.** `HttpClient::DEFAULT_BASE_URL = 'https://gp.useyona.com'` serves sandbox and live. The
  name is permanent; infrastructure moves by DNS, never by changing it. Never switch hosts by mode:
  the key prefix (`sk_test_` / `sk_live_`) is the mode. `base_url` is an advanced override only. The
  SDK never reads an environment variable; the only hook is the constant
  `USEYONA_EINVOICE_BASE_URL_OVERRIDE`, defined by `scripts/examples-preload.php` alone.
- **Errors** come from the envelope: `meta.errorCode`, `meta.message`, `meta.errors`
  (single-key objects), `meta.requestId` (fallback `x-request-id`).
- **Retries** only for GET/PUT/DELETE and requests carrying an `Idempotency-Key`. A service passes
  `idempotent => true` only for routes whose backend reads `Idempotency-Key`; PATCH routes send it
  only when the caller gives `$options->idempotencyKey`.
- **Timeouts and delays are seconds** (floats); einvoice-js uses milliseconds. PSR-18 has no
  per-request deadline: the timeout is set on the client the SDK builds (Guzzle); an injected client
  keeps its own. A `NetworkExceptionInterface` whose message mentions a timeout is a
  `TimeoutException`, any other one a `ConnectionException`.
- **Bodies and answers are plain arrays** (`json_decode(…, true)`), typed for phpstan with the
  generated shapes (`@phpstan-import-type CreateInvoiceBody from \Useyona\EInvoice\Generated\Types`).
  An empty array body is sent as `{}`. Enums are closed literal unions; the API may add values.
- **Webhooks**: HMAC-SHA256 over `t + "." + raw body`, header `Yona-Signature: t=…,v1=…[,v1=…]`,
  ±300 s, `hash_equals`. The vectors in `tests/vectors/` come from the backend signer, via einvoice-js.

## Guides (examples/ → guides/guides.json)

- Each `examples/<id>.php` is one recipe: header `// @recipe <id> <Title>` + `// @summary <text>`,
  then steps `// @step <id> <Title>`, optionally followed directly by `// @text …`, `// @op
  <operationId>` and `// @quickstart`. A step's code runs until the next `@step`; the header before
  the first step (`<?php`, `declare`, `require`, `use`) is hoisted into it. Recipe and step ids are the
  same in every SDK so the portal can tab between languages.
- Examples `require 'vendor/autoload.php'`, pass only `'api_key' => (string) getenv('YONA_API_KEY')`,
  and must exit non-zero when what they show does not hold.
- After changing an example: `make lint`, `make guides`, commit `guides/guides.json`
  (`tests/GuidesTest.php` fails when it is stale), and run it live (`make examples`).

## Adding or changing a method

1. Bump `EINVOICE_JS_REF` in `scripts/sync.sh` to the einvoice-js commit (or tag) that has the change,
   `make sync`, read the diff of the snapshot and of `src/Generated/Types.php`.
2. Add the method to the service of its API tag, documented with the generated `<Op>Query` /
   `<Op>Body` / `<Op>Data` / `<Op>Item` shapes, named as einvoice-js names it; or add the operation
   to `ExcludedOperations` with a reason.
3. A docblock on every public method (what it does, the capability it needs, charging, idempotency).
4. `make test` (the parity test fails until both directions agree), `make lint`.
5. Update README (API reference) and CHANGELOG.

## Conventions

- Conventional commits: `type(scope): subject`. Scopes: client, invoices, submissions, output, items,
  reference, inbound, sellers, buyers, billing, webhooks, organization, parity, smoke, types, config,
  deps, release. **Never add Claude or any AI assistant as co-author.**
- phpstan level 8 and php-cs-fixer (PSR-12) over `src`, `tests`, `examples`, `scripts`; the generated
  file is excluded from the fixer and from coverage. Tests use a fake PSR-18 client
  (`tests/Support/FakeHttpClient.php`), never the network.
- Coverage threshold 80 % (CI, with pcov).
- Releasing: bump `Version::VERSION`, update CHANGELOG, `make guides`, merge to `main`; CI tags
  `v<version>` and Packagist updates from its GitHub hook (PUBLISHING.md).
